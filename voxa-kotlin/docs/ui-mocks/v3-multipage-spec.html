How the Auth cleanup works (technical note)

The WebView injects a small CSS+JS payload in onPageFinished only when the URL is on chatgpt.com/auth/*. The injection does three things, and nothing else:

  1. Vertical-center the login form using flexbox on the page's main container. Fixes the "content jammed at top, whitespace below" complaint.
  2. Hide marketing chrome — best-effort: hides elements whose visible text matches phrases like "Try ChatGPT", "Get free access", "Plus", "Pro" when they sit outside a <form>, <input>, or <button[type=submit]> (so we never break the actual login). Also hides anchors that link to /pricing or marketing.openai.com.
  3. Suppress horizontal scroll and set html, body { background: #FFFFFF; min-height: 100vh; } so the empty area looks intentional, not broken.

The injection runs once per page-finished event and re-runs on a 2-second MutationObserver tick (ChatGPT's auth flow is an SPA). If OpenAI changes the page structure tomorrow, the worst case is the marketing chrome reappears — login itself never breaks because the safety guards skip anything inside the form. Auth scouting via agent-browser was attempted but Cloudflare Turnstile blocked the headless session; the real app's Chrome UA + cookie state passes CF, so this only affected reconnaissance, not the runtime.
